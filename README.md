# 列表协调升级验收台（Reconciler Acceptance Bench）

给组件库维护团队使用的验收工具：在浏览器里对一棵**带稳定 key 的列表组件树**做重排、插入、删除和切换
key，逐步查看 React 风格协调器产出的补丁，并直接观察每行组件的**输入框、计数器、可折叠行**等
*内部状态*在更新后归属于哪个实例——用来确认升级协调逻辑后没有把状态错误地换到别的项目上。

全部逻辑在浏览器本地运行，无后端、无外部服务。

## 它在验证什么

React 列表协调的核心约定：

- **按 key 匹配实例**：同 key 的行在重排时被复用并移动 DOM，内部状态（`useState` 等）原样保留；
- **新 key = 挂载**：出现旧树里没有的 key 时创建新实例，输入框回到挂载初始值、计数器归零；
- **消失的 key = 卸载**：旧实例及其内部状态一并销毁；
- **重复 key 是未定义行为**：React 会在控制台报警，匹配退化为尽力而为，状态可能挂到错误的项目上。

本工具把这套规则同时实现了两遍，方便对照验收：

1. **右侧真实组件 `RowItem`**：输入框 / 计数器 / 折叠态是真正的 React `useState`，以 `key={item.key}`
   渲染，状态保留与否完全由 React 决定（不是预制动画）；
2. **纯函数协调引擎 `src/core/reconcile.ts`**：用与 React 相同的 `lastPlacedIndex` 规则预测每个实例
   是挂载 / 移动 / 保留 / 卸载，产出一串可单独执行的补丁；每步执行后用真实数据驱动右侧界面，
   并把「引擎预测的节点身份」与「React 真实实例身份」并排展示、自动比对。

## 页面操作指南

页面分四栏（左一右三）：

1. **① 目标树编辑** —— 描述更新*之后*想要的树：
   - 每行可编辑 `key`、标题、挂载初始文本；
   - 行操作：上移 / 下移、后面插入新 key、**复制同 key 行**（制造重复 key）、
     **切换为他人 key**（制造身份交换 / 重挂载）、删除；
   - 顶部：整体反转、末尾插入、重置示例、**生成补丁 →**；
   - 目标树出现重复 key 时即时红色提示。
2. **② 补丁步骤** —— 协调引擎产出的有序步骤（先卸载，再按目标顺序挂载 / 移动 / 保留）：
   - **单步执行 ↷**、**撤销一步 ↶**、**全部执行**、**回到补丁前**；
   - 每步带可读说明、执行时刻下标、移动锚点（插在哪个实例之前 / 追加末尾）；
   - 重复 key 相关步骤高亮，警告（error/warn/info）集中展示。
3. **③ 真实渲染结果** —— 由已执行补丁驱动的真实 React 列表：
   - 每行有可编辑输入框、+/- 计数器、折叠/展开，均为组件内部状态；
   - 行上同时显示 `key`、引擎预测身份 `node-*`、React 真实实例身份 `inst-*`；
   - 全部步骤执行完自动给出「验收通过 / 失败」：每个位置的身份与 key 必须与预测一致。
4. **④ 节点身份流水** —— 真实组件 `useEffect` 上报的挂载 / 卸载事件：
   - 同 key 重排应当**零事件**（复用，状态保留）；
   - 切换 key 会看到成对的「旧 key 卸载 → 新 key 挂载」。

### 推荐验收剧本

1. **状态跟随实例**：在项目甲的输入框写字、计数加到 2、折叠行 → 整体反转 → 生成补丁 → 全部执行。
   观察甲的内容/计数/折叠态随甲移动，且身份流水为空。
2. **切换 key 即重置**：把某行 key 改成另一行的 key 或新 key → 执行，观察输入框回到挂载初始值、
   计数器归零，流水出现卸载+挂载。
3. **插入/删除**：在中间插入新 key 或删除中间行，单步执行观察后续兄弟如何被锚点移动，其余行状态不变。
4. **重复 key**：点「复制同 key 行」生成补丁，观察 error 警告、被高亮的步骤，以及副本为何拿到了
   全新实例（新挂载）而不是原实例的状态。
5. **撤销/重做**：执行若干步后逐步撤销或「回到补丁前」，被卸载的实例会带着相同身份与 key 回来。

## 目录结构

```
src/
  core/
    types.ts       数据模型：ItemData / PatchStep / ReconcileWarning / ReconcilePlan
    factory.ts     实例 id 生成、示例数据
    draft.ts       左侧草稿树的编辑操作（移动/插入/删除/反转/复制同 key/切换 key）
    reconcile.ts   协调引擎：key 匹配、lastPlacedIndex 移动判定、锚点插入、
                   重复 key FIFO 贪心匹配与警告、applyStep 单步执行
    history.ts     补丁快照历史：单步前进/撤销/重做/回退
  components/
    RowItem.tsx        被验收的真实组件（输入框/计数/折叠 = 真正的 useState）
    DraftEditor.tsx    ① 目标树编辑器
    PatchPanel.tsx     ② 补丁步骤面板
    ResultPanel.tsx    ③ 真实渲染结果 + 身份自动比对
    IdentityPanel.tsx  ④ 挂载/卸载流水
    lifecycle.ts       生命周期上报 Context
  App.tsx          组装与状态编排
  test/            vitest 测试（setup + 4 个测试文件）
```

## 测试覆盖

共 30 个用例（`npm test`）：

- **key 匹配**（`reconcile.test.ts`）：不变全复用、反转、前置、新 key、改名（卸载+挂载）、key 互换；
- **状态保留**：移动沿用原 id、挂载拿到新 id/seed、删除 id 消失、同 key 改标题仅更新 props；
- **移动 / 插入 / 删除**：混合变换逐步执行结果与预测一致、删除步骤下标随执行时刻变化、空树边界；
- **重复 key 警告**：目标树重复报 error 并标记步骤、当前列表已重复报 warn、FIFO 贪心归属；
- **历史栈**（`history.test.ts`）：单步、撤销、重做、直达终点/起点、边界空操作；
- **真实 React 行为**（`RowItem.test.tsx`）：重排保留输入/计数/折叠、换 key 重置、删除不影响他人、
  生命周期流水、React 对重复 key 的控制台警告；
- **端到端**（`App.test.tsx`）：反转剧本验收通过、重复 key UI 警告、新 key 挂载初始化、删除与回退。
