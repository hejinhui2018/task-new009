# 列表更新验收台（Reconciliation Acceptance Bench）

给组件库维护团队用的升级验收工具：在浏览器里本地验证**列表重排、插入、删除、换 key 之后，组件内部状态有没有被错误地换到别的项目上**。

实现方式不是播放预制动画——页面内置了一个 keyed 协调器（`src/reconciler/`）：左侧编辑的目标树先被 diff 成一串**补丁步骤**（mount / move / update / replace / unmount），补丁逐步应用到实例列表上，右侧界面渲染的就是补丁应用后的真实结果。每个组件实例的局部状态（输入框文本、计数器、折叠状态）都存在实例上，跟着实例身份走。

## 运行方式

```bash
npm install        # 安装依赖
npm run dev        # 开发模式（默认 http://localhost:5173）
npm test           # 运行全部测试（vitest run）
npm run build      # 生产构建（tsc -b && vite build）
npm run preview    # 预览生产构建产物
```

要求 Node.js ≥ 18（开发用的是 Node 22）。

## 页面与使用流程

```
┌──────────────────────┬  ────────────────────────────────┐
│ ① 草稿树（编辑目标）     │ ② 渲染结果（由补丁驱动）        │
│   key / 类型 / 标签      │   每行：颜色点 + #实例ID + key  │
│   重排 插入 删除         │   行内可直接输入/计数/折叠      │
│   重复 key 切换 key      ├────────────────┬───────────────┤
│   [生成补丁]            │ ③ 补丁步骤      │ ④ 节点身份     │
│                          │   单步/全部/放弃 │   实例详情     │
└──────────────────────┴────────────────┴───────────────┘
```

1. 在 **② 渲染结果** 里先给一些行输入内容、点几下计数器、展开折叠行——这些就是组件的局部状态。
2. 在 **① 草稿树** 里做修改：工具栏有「反转顺序 / 随机重排 / 删除末行 / 制造重复 key / 切换首行 key」，每行还有上移 ↓、下移 ↑、复制为重复 key ⧉、换新 key ⇄、删除 ✕，也可以直接改 key、改组件类型、改标签、添加行。
3. 点 **生成补丁**：**③ 补丁步骤** 列出这次更新的全部补丁，草稿行和渲染行上会出现命运徽章（复用 / 移动 / 挂载 / 替换 / 卸载）。
4. 点 **单步执行** 逐步应用补丁（或 **全部执行** 一次跑完），右侧渲染随每一步真实变化；**放弃补丁** 回滚到生成前的状态。
5. 点击任意渲染行，在 **④ 节点身份** 里看实例 ID、key、组件类型和局部状态 JSON；行首颜色与 `#编号` 即节点身份，重排时可以肉眼追踪它去了哪一行。
6. 补丁全部执行完自动提交；顶栏的 **撤销 / 重做** 以「一次更新」为单位回退，**重置** 回到初始示例。

## 验收语义（与 React 一致）

| 场景 | 结果 |
| --- | --- |
| key 相同 + 组件类型相同 | **复用**实例，局部状态保留；位置变了记一条 `move` |
| key 相同 + 组件类型不同 | **replace**：旧实例卸载、新实例挂载，状态重置 |
| key 只在新树里 | **mount**：新建实例，初始状态 |
| key 只在旧树里 | **unmount**：实例销毁，状态丢失 |
| 只改了标签等 props | **update**：就地更新，状态保留 |
| 新树里 key 重复 | 告警；只有第一个匹配复用旧实例，其余重新挂载（状态可能错位） |

## 项目结构

```
src/
  reconciler/
    types.ts   # SpecItem / Instance / PatchOp / Plan 等类型
    diff.ts    # computePlan：旧实例列表 + 目标草稿 → 有序补丁 + 告警
    apply.ts   # applyOp / applyAll：纯函数应用补丁（不可变更新）
  store.ts     # useReducer 状态：提交基线、草稿、补丁进度、撤销/重做
  lib.ts       # 标签、身份颜色、补丁描述等工具
  components/
    TreeEditor.tsx    # ① 草稿树编辑
    RenderedList.tsx  # ② 渲染结果（输入框/计数器/折叠行）
    PatchPanel.tsx    # ③ 补丁步骤
    Inspector.tsx     # ④ 节点身份
tests/
  diff.test.ts   # key 匹配、移动/插入/删除、重复 key 告警、replace/update
  state.test.ts  # 状态保留、单步执行与一次性执行等价
  ui.test.tsx    # 端到端：重排后状态跟随实例、换 key 丢状态、警告、撤销重做
```

## 测试

```bash
npm test
```

覆盖四块验收点：

- **key 匹配**：按 key 而非位置复用——两个同类型输入框交换位置后，各自的内容不串；
- **状态保留**：重排 / 插入 / 删除后，幸存实例的文本、计数、折叠状态原样跟随，且单步执行与一次性执行结果一致；
- **移动 / 插入 / 删除**：补丁序列的类型、下标与最终顺序正确，卸载倒序进行；
- **重复 key 警告**：草稿出现重复 key 时产生告警，且只有第一个匹配复用旧实例。
